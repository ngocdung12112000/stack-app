stackshop-infra: what each file does

Everything the app needs around the code: local databases, monitoring, Kubernetes and checks. No application code lives here.

local/ runs the tools on your PC→ monitoring/ watches the services→ k8s/ describes the real deployment→ argocd/ applies it to the cluster→ .github/ checks it all in CI

local/ — run everything on your computer

Used by docker compose -f local/compose.yml up -d.

local/compose.yml

Starts MySQL, MongoDB, Redis, Mailpit, Prometheus and Grafana and creates the Docker network stackshop that the backend also joins.

local/init/mysql/01-schemas.sql

Runs on first MySQL start: creates the identity database and a user limited to it.Dev passwords only.

local/init/mongo/rs-init.js

Turns Mongo into a one-node replica set (rs0) so it supports transactions. Runs as the container health check and is safe to repeat.

local/init/mongo/.gitkeep

Empty marker so Git keeps the folder.

local/grafana/provisioning/datasources/prometheus.yml

Tells Grafana at startup: “your data source is the Prometheus at prometheus:9090”. No manual setup.

local/grafana/provisioning/dashboards/stackshop.yml

Tells Grafana to load every dashboard JSON from monitoring/dashboards into a folder called StackShop.

monitoring/ — see problems before users do

Dashboards, alert rules, how to react, and tests for the alerts.

monitoring/prometheus/prometheus.yml

Local Prometheus config: scrape gateway, catalog, identity every 15s and load the alert rule files.

monitoring/rules/identity.rules.yaml

Source of truth for the 6 identity alerts (token reuse, lockout, throttle, down, high 5xx, slow p95). Written as a Kubernetes PrometheusRule.

monitoring/prometheus/rules/identity.rules.yml

Generated copy of the file above in the plain format local Prometheus reads. generatedDo not edit by hand.

monitoring/scripts/render-local-rules.py

Produces the generated copy. CI runs it with --check to make sure the two files never drift apart.

monitoring/rules/tests/identity.test.yaml

Unit tests for the alerts: feeds fake numbers and checks each alert fires (or stays quiet) at the right time.

monitoring/dashboards/identity-auth.json

The Grafana dashboard “Identity & Auth”: logins, refresh tokens, request rate, errors, latency, memory.

monitoring/kustomization.yaml

Packs the rules and the dashboard so Kubernetes (via ArgoCD) can deploy them to the monitoring namespace.

monitoring/runbooks/identity-login-abuse.md

What to do when lockout/throttle alerts fire or identity is down.

monitoring/runbooks/identity-refresh-reuse.md

What to do when a refresh token is reused (possible stolen token).

monitoring/runbooks/identity-service-health.md

What to do for high 5xx or slow responses: check MySQL, Redis, memory, thread pool.

k8s/apps/identity/ — how identity runs on Kubernetes

Kustomize: base/ is shared, each overlays/ folder changes it for one environment.

README.md

Explains the keys the identity-secrets Secret must contain and how it is created per environment.

base/kustomization.yaml

Lists the files below as one package and holds the image name.

base/deployment.yaml

Runs 2 identity pods: health probes, non-root, read-only filesystem, JWT signing key mounted from the Secret.

base/service.yaml

Stable address identity:8080 so the gateway can find the pods.

base/configmap.yaml

Non-secret settings: token lifetime, lockout limits, email host.

base/migration-job.yaml

Runs the database migration once before each deploy (ArgoCD PreSync), so pods never migrate themselves.

base/hpa.yaml

Auto-scales from 2 to 5 pods when CPU passes 70%.

base/pdb.yaml

During node maintenance, always keep at least 1 pod alive.

base/networkpolicy.yaml

Only the gateway and Prometheus may call identity. Outbound only to DNS, MySQL, Redis and SMTP.

base/servicemonitor.yaml

Tells Prometheus to scrape identity’s /metrics.

base/serviceaccount.yaml

The pod’s identity inside the cluster (no API token mounted).

overlays/dev/kustomization.yaml

Dev: 1 replica, no autoscaler or PDB, smaller resources, dev frontend URL.

overlays/staging/kustomization.yaml
overlays/staging/sealedsecret.yaml

Staging settings and an empty SealedSecret placeholder (must be sealed against the real cluster).

overlays/prod/kustomization.yaml
overlays/prod/externalsecret.yaml

Prod: real URLs and SMTP, up to 6 pods. Secrets come from AWS Secrets Manager; the file holds key names only.

k8s/.gitkeep

Empty marker so Git keeps the folder.

argocd/apps/ — GitOps

Tells ArgoCD “watch this Git path and keep the cluster identical to it”.

identity-dev.yaml
identity-staging.yaml
identity-prod.yaml

One ArgoCD Application per environment, each pointing at the matching k8s/apps/identity/overlays/<env> folder. not running yetNo cluster or ArgoCD is installed locally.

.github/ — automatic checks

.github/workflows/validate.yml

On every push: validate Prometheus config and rules, run alert tests, check dashboards, build each Kustomize overlay and lint it (kubeconform, kube-linter).

Repo root

CLAUDE.md

Short guide for Claude Code: commands, ports, Mongo connection strings, monitoring workflow.

.gitignore

Keeps .env and OS junk out of Git.

Good to know Only identity has manifests and monitoring so far. Gateway, catalog and later services get theirs as they are added. Nothing here has been applied to a real cluster yet; local Docker and CI validation are what is proven.
